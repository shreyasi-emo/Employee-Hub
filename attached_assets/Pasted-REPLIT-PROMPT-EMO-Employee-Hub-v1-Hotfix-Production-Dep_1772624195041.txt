1) FIX FORGOT PASSWORD / RESET FLOW (critical takeover fix)

CURRENT BUG:
- /api/auth/forgot-password returns a resetUrl, and the UI displays it.
This allows anyone to reset anyone’s password.

REQUIRED FIX:
A) Public forgot-password endpoint:
- POST /api/auth/forgot-password
  - Input: { email }
  - Response: ALWAYS { success: true } regardless of whether user exists
  - Server should NOT return resetUrl or token
  - Server should create a reset token if user exists, store hashed token + expiry in DB
  - If SMTP configured, send email; if not, do nothing

B) HR-only reset link generator endpoint:
- POST /api/hr/users/:userId/generate-reset-link
  - Auth: HR_ADMIN only (or SUPER_ADMIN/CEO if exists)
  - Response: { resetUrl } (safe because HR-only)
  - Audit log: who generated it + for which user + timestamp
  - Token expiry: 2 hours

C) UI changes:
- Login page: keep “Forgot password” but DO NOT show resetUrl
  - Show message: “If the account exists, you’ll receive instructions.”
- Add an HR-only admin page action:
  - From Employee Profile → “Generate password reset link” (HR only)
  - Copy-to-clipboard link

D) Security:
- Tokens stored hashed (never store raw token)
- Rate limit forgot-password endpoint

2) DISABLE SEEDING IN PROD (no default admin, no fake employees)

CURRENT BUG:
- seed() runs on server boot and creates superadmin/Admin@123 and fake employees.

REQUIRED FIX:
- Remove seed() call from server startup.
- Create a separate script: npm run seed
- Guard seeding:

- In production, system must start with NO users.
- Add a “bootstrap” flow:
  - If no users exist, allow creating the FIRST admin only using a one-time BOOTSTRAP_TOKEN env var.
  - Endpoint: POST /api/auth/bootstrap (requires BOOTSTRAP_TOKEN header)
  - After first admin created, bootstrap endpoint becomes disabled.
