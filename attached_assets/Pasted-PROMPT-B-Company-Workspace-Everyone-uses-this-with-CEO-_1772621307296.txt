PROMPT B — Company Workspace (Everyone uses this) with CEO-Only Approvals (v1)

CONTEXT
Add a “Company Workspace” used by ALL employees for office operations and requests. It must integrate with Office Admin Ops module (Prompt A) for processing and with the generic approval engine (CEO-only in v1).
This is the company-wide “office OS” alongside the separate Engineering/PLM system.

APPROVAL POLICY (v1)
- All submitted requests route to CEO_APPROVER for final approval in v1.
- Implement via the same generic approval engine so later we can change to managers per team without rewrites.

ROLES
- EMPLOYEE: create/view own requests; comment; upload attachments; see status timeline
- MANAGER: in v1, manager is watcher only (no approvals yet) but can see team requests for visibility
- OFFICE_ADMIN: processes approved requests (ordering/booking/ticket handling)
- FINANCE: updates payment statuses
- CEO_APPROVER: final approval inbox

MODULES

1) Service Catalog Home (front door)
Tiles:
- Purchase Request (Amazon/office/equipment)
- Travel Request
- Admin/Office Ticket (stationery/repairs/guest access/etc)
- IT Ticket (optional; can be same ticket type)
- Forms & Policies (Company Drive)
- My Requests (all request timelines)
- Team Requests (manager visibility)
- Announcements + Policy Acknowledgements

2) Purchase Request (employee UI)
- Form: category, items (desc/qty/link), estimated cost, needed-by date, justification, attachments
- Status flow:
  Draft -> Submitted -> Pending CEO -> Approved/Rejected -> Ordered -> Received -> Closed
- Employee can edit only while Draft or ChangesRequested.
- Once Approved, employee cannot change; can comment.

3) Travel Request (employee UI)
- Form: purpose, from/to, dates, preferences, constraints, attachments
- Status flow:
  Draft -> Submitted -> Pending CEO -> Approved/Rejected -> Booked -> Completed -> Closed
- Booking details visible after Office Admin updates.

4) Tickets / Helpdesk (employee UI)
- Ticket categories: stationery/office/repairs/guest/IT/etc
- Status: Open/InProgress/NeedInfo/Done/Cancelled
- CEO approval not required for ticket creation; ONLY required if ticket has “purchase/travel/payment” action.
- Keep tickets as operational; Office Admin can resolve without CEO unless it triggers PR/Travel/Payment.

5) My Requests + Timelines
- Unified view showing PR/Travel/Tickets/Payments related to the employee
- Each item shows:
  status chip, approval status, timeline events, comments, attachments

6) Manager Visibility (no approvals in v1)
- “Team Requests” page for managers:
  - see team members’ submitted requests + statuses (read-only)
  - comment capability (optional)
- Later this will become manager approval by configuration; design data model accordingly (use approval engine).

7) Notifications (in-app required)
- Submission confirmations
- CEO decision updates
- Office Admin updates (ordered/booked/need info)
- Ticket status changes
- Policy acknowledgement reminders

8) Company Drive + Policies
- Employees can view allowed folders
- Policies can require acknowledgement; show pending acknowledgements on dashboard
- Keep employee private docs separate.

SECURITY RULES
- Employee can only view own requests and attachments.
- Manager can view team requests only (scoped by reporting chain).
- Office Admin can view all operational queues.
- CEO sees all items in approval inbox (from Prompt A approval engine).
- Finance sees payment tracker items only.

DELIVERABLES
- Company Workspace UI fully working with PR/Travel/Tickets + request timelines + notifications
- Integrated with Office Admin Ops processing (Prompt A) and generic approval engine
- Manager visibility page (read-only in v1)
- Future-ready: workflows configurable later for manager approvals per team (do not hardcode CEO-only into schema)
