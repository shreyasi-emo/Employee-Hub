- Consistency: statuses and terminology must be consistent across UI/API/DB.
- Deployment safe: app must start on process.env.PORT, bind 0.0.0.0, and validate env vars on boot.

PRIORITY ORDER (build in this order): P0 → P1 → P2

P0 (Release blockers)

1) Remove all demo credentials + fake admin shortcuts
- Remove any “demo creds”, hardcoded users, and seeded passwords from UI/README.

2) Branding cleanup

- Create a config file for brand name/logo and use it across UI.

3) Identity + Employee ID + @emoenergy.in login provisioning (must be bulletproof)
Goal: Employee login should be tied to work email identity, with invite/reset onboarding.
Implement:
- Enforce allowed email domain list (default: emoenergy.in) for employee logins.
- Employee ID generation:
  - Auto-generate employeeCode on employee creation (sequence-based: EMO-0001…)
  - employeeCode must be immutable once assigned.
- Account provisioning rules:
  - HR creates Employee record with workEmail.
  - System auto-creates User account in “Invited” status if not exists.
  - Generate invite token (expiry) and send invite OR display link if email not configured.
  - Employee sets password via invite link (same UX as “forgot password”).
- Do NOT implement “auto login”. Implement: invite/reset = set password + then login.
- On employee exit: auto-suspend user login.

Acceptance:
- A newly added employee can access the system only after invite/reset completes.
- Work email is unique and is the primary username.

4) Environment + deployment hardening
- Server must listen on: PORT = process.env.PORT || 5000, host 0.0.0.0
- Add boot-time env validation with clear errors:
  - DATABASE_URL, JWT_SECRET, and any required config must be present.
- Add global error handlers: unhandledRejection + uncaughtException logging.

P1 (Core HR usability / operations)

- Optional roster: per-date overrides for rotating shifts.
UI:
- Admin creates shifts.
- Admin assigns shifts to one employee OR bulk assigns to many employees.
- Roster/timetable view for week/month for HR and managers.
Attendance:

7) Company-wide “Drive” (folders/files for org review)
Implement:
- Folder hierarchy + permissions:
  - folders (parent/child)
  - ACL by role and/or group (view/upload/manage)
- Company documents separate from employee personal docs.
- Features: upload, download, search, tags, optional versioning.
- Support “Policy docs” here as well.

Acceptance:
- HR can publish files to company drive; employees can view based on permission.
- Sensitive employee docs remain private.

8) Onboarding module (checklists + accountability)
Implement:
- Onboarding templates: tasks owned by HR/IT/Manager with due dates.
- Onboarding instances per employee auto-created when status = “Joining scheduled” / “Active”.
- Views:
  - HR onboarding dashboard (all joiners + task progress)
  - Manager view (their owned tasks)
  - Employee view (their tasks)

Acceptance:
- HR can run onboarding for 5–20 joiners without spreadsheets.

9) Notifications (in-app required, email optional)
In-app:
- notifications table: user_id, type, title, body, link, read_at
Triggers:
- Leave applied → notify manager
- Attendance regularization submitted → notify manager
- Approval/rejection → notify employee
Email:
- If SMTP configured, send emails; else show “copy link” fallback.

Acceptance:
- Managers get an approvals queue + notifications.
- Employees can see status changes without chasing HR.

10) Status + approval logic (standardize + add timeline)
Standardize statuses across attendance/leave:
- Leave: Pending / Approved / Rejected / Cancelled
- Regularization: Pending / Approved / Rejected / HR Overridden
Add a status timeline with timestamps + actor notes.
Important rule:
- Once payroll for the month is locked, changes that affect LOP are blocked (or require HR unlock).

Acceptance:
- UI shows consistent chips and history everywhere.

11) “Manager can edit state later” — implement safely
Do NOT allow silent overwrites.
Rules:
- Manager can change decision ONLY while request is Pending.
- After Approved/Rejected:
  - Only HR can “Reopen” (mandatory reason + audit log + notification).
  - Optional: allow manager reversal within a short window (e.g., 2 hours) WITH reason and HR notified.
- Any override must be audited.

Acceptance:
- No approval flip-flops without traceability.
