FINAL MASTER PROMPT — Build “EMO Office OS” (Company-wide + HR/Admin) as the ONLY office-level system

CONTEXT / GOAL
We are building a single company-wide “Office OS” web app that replaces spreadsheets/WhatsApp/random tools for all non-engineering ops. Engineering/PLM remains separate. Finance uses Zoho, comms via Gmail/Drive, PM in Notion — but THIS Office OS is the source of truth for:
- People: HRIS + Attendance/Leave + Performance/OKRs + Employee lifecycle
- Hiring: ATS recruitment end-to-end
- Office Ops: Procurement, travel, admin/IT helpdesk, vendors, payment tracking with finance comms
- Knowledge: company drive, policies, templates, announcements
- Intelligence: dashboards, KPIs, org/team health metrics, CEO cockpit
- Integration: deep-link and sync metadata with Notion + Google (Drive/Gmail/Calendar) where possible; otherwise stubs.

HARD POLICY (v1)
- All approvals go to CEO_APPROVER by default (single approver).
- DO NOT hardcode CEO-only logic in schema. Use a configurable Approval Engine and set default workflows to CEO. Future: managers/multi-step per team without schema rewrite.

TWO WORKSPACES (same app, strict RBAC)
1) Company Workspace (everyone): self-service requests, policies/docs, announcements, OKRs, dashboards, my tasks, my approvals visibility.
2) HR/Admin Workspace (restricted to HR/Office Admin/CEO): ATS, HR ops control room, office admin processing, vendor registry, payment tracker, lifecycle control.

NON-NEGOTIABLES
- Server-side RBAC + scope checks everywhere. No UI-only permission logic.
- Immutable timelines + audit logs for every sensitive action (approvals, overrides, edits).
- Unified search across entities (docs, employees, candidates, requests) with permission filtering.
- Unified notifications center (in-app mandatory; email optional).
- Deployment-safe: listen on process.env.PORT, bind 0.0.0.0, env validation on boot.

TECH STACK (use exactly)
- Frontend: Next.js (TypeScript) + Tailwind
- Backend: Node.js (NestJS preferred, else Express w/ clean layering) + TypeScript
- DB: Postgres + Prisma migrations
- Auth: JWT + refresh tokens + optional Google SSO (domain-restricted)
- Files: S3-compatible storage (local dev ok)
- Queue/Scheduler: BullMQ+Redis OR DB cron
- Docker Compose for local/prod-like run

PLATFORM FOUNDATION (BUILD FIRST)

A) IDENTITY & AUTH
- Enforce work email domain allowlist (default: emoenergy.in).
- Support BOTH:
  1) Invite/reset password onboarding (HR creates employee -> invite -> set password)
  2) Google SSO (OpenID Connect) restricted to emoenergy.in (optional but recommended)
- EmployeeCode auto-generated: EMO-0001… (sequence), immutable once assigned.
- User status: Invited / Active / Suspended / Exited. Exit auto-suspends access.
- Field masking rules for sensitive data (bank/Aadhaar masked by default).

B) GENERIC APPROVAL ENGINE (single engine used everywhere)
Data model:
- approval_workflows (entity_type, name, active)
- approval_steps (order, approver_role default CEO_APPROVER, optional conditions later)
- approval_requests (entity_type, entity_id, workflow_id, status, created_by, created_at)
- approval_decisions (append-only: actor, decision, comment, timestamp, step_order)
Rules:
- Decisions immutable; reopen requires reason + audit + new decision cycle.
- Supports Approve/Reject/RequestChanges with mandatory comment on Reject/RequestChanges.
UI:
- CEO Inbox = unified queue across all entity types.
- Entity detail shows approval timeline and resubmit option.

C) TIMELINES + AUDIT LOGS (immutable)
- timeline_events (entity_type, entity_id, actor_user_id, event_type, message, metadata_json, created_at)
- audit_logs (actor, action, entity, before/after json, reason_required boolean, created_at)
Require reason + audit for:
- overrides (attendance/leave), salary/CTC edits, unlocking locks, vendor bank edits, payment status edits, offer edits post-submit.

D) NOTIFICATIONS + REMINDERS
- notifications table (user_id, type, title, body, link, read_at)
- scheduler for reminders: approvals pending, interview feedback pending, follow-ups due, lifecycle deadlines, policy acknowledgements due.

E) GLOBAL SEARCH
- Search endpoint + UI: employees, candidates, requisitions, requests, documents, policies, tasks.
- Permission-filter results strictly server-side.
- Use Postgres full-text search (tsvector) and maintain search indices.

F) CONFIG / ORG MODEL
- company entities, locations, departments, cost centers, bands/grades (min viable)
- reporting chain (manager_id) with effective-dated history
- custom fields builder for employee/candidate/request (typed + validation)

MODULE GROUP 1 — HRIS CORE (Company + HR Workspace)

1) Employee Directory + Profile (HR/Admin editable; employee limited self-edit)
- Tabbed profile: Personal, Employment, Org/History, Documents, Assets, Attendance/Leave summary, Performance/OKR, Hiring History (HR-only).
- Effective-dated changes: manager/department/band/location/designation.
- Employee self-service edits limited to address/emergency contacts/phone (config).

2) Attendance + Shifts + Rosters
- Shifts table + effective-dated shift assignments; optional roster overrides.
- Attendance regularization workflow with approvals + timeline.
- Late/early calc based on assigned shift. Overtime optional.

3) Leave + Holidays
- Leave ledger (immutable accrual/debit/adjust/expiry), policies, comp-off, optional/restricted holidays.
- Leave requests with approval + timeline + notifications.

4) Onboarding / Offboarding
- Template checklists (HR/IT/Manager owners) + instances per employee.
- Exit workflows: clearance, assets return, F&F checklist (not full accounting).

5) Documents / Company Drive / Policies
- Folder tree + ACL (role/user/group). Separate “Company Drive” vs “Employee Private Docs”.
- Policy docs with “Acknowledgement required” + tracking report.

6) Assets
- Company asset registry + assignment/return workflow; ties into onboarding/offboarding.

──────────────────────────────────────────────────────────────────────────────
MODULE GROUP 2 — PERFORMANCE + OKRs + COMPANY INTELLIGENCE

A) OKRs / Goals (Company/Team/Individual)
- OKR cycles: quarterly/half-year, status Draft/Active/Locked/Archived.
- Objectives with Key Results, owners, alignment (KR links upward), scoring.
- Check-ins: weekly/monthly updates, progress %, confidence, blockers.
- Views:
  - Employee: my OKRs, team OKRs, company OKRs (permission-based).
  - Manager: team roll-up with health.
  - CEO cockpit: company-level progress + lagging areas.

B) Performance Reviews (integrate with OKRs)
- Review cycles: self + manager + optional peers; rating scales; calibration optional.
- Link goals/OKRs into review forms.
- Lock/finalize semantics; reopen only via HR_ADMIN with reason + audit.

C) Company Intelligence Dashboards (CEO + Leadership + HR + Office Admin)
Build role-based dashboards with drill-down:
- Org health: headcount by dept/location/band, joiners/leavers, attrition
- Hiring funnel: open reqs, time-to-hire, stage aging, offer acceptance rate
- Ops SLAs: PR/travel/ticket aging, overdue items, payment aging
- People ops: attendance anomalies, leave liability, onboarding overdue, policy acknowledgement gaps
- Performance health: OKR completion %, team confidence trends
Rules:
- CEO gets full view; others see scoped views.

D) CEO COCKPIT (must)
- Unified approvals inbox (from approval engine)
- Top alerts: overdue payments, stuck hiring stages, overdue onboarding, policy gaps, critical tickets
- Quick actions: approve/reject, assign owner, add comment.

──────────────────────────────────────────────────────────────────────────────
MODULE GROUP 3 — ATS RECRUITMENT (HR/Admin Workspace)

1) Agency Vendor List (minimal)
- agencies table (active/inactive), contacts, docs folder link. No complex contract tracking.

2) Requisitions
- Draft -> Submit -> Approved(Open) via CEO approval (default).
- Kanban pipeline per requisition, SLA per stage.

3) Candidates + Applications
- Candidate dedupe (email/phone) + merge flow (HR_ADMIN only).
- Application timeline (stage moves, comm logs, approvals).

4) Interviews + Scorecards
- Interview scheduling, interviewer assignment, feedback locked.
- Reminders for pending feedback.

5) Offer Management
- Offer draft -> Submit -> CEO approve -> send -> accept/decline.
- Offer letter templates + PDF stored in restricted drive folder.
- Offer accepted -> prejoin -> joined -> auto-create employee + invite + onboarding.

6) Approvals rule (v1 default)
- CEO approval required for: requisition opening + offer approval.
- Hiring managers/interviewers contribute feedback but do not finalize approvals in v1.
- Keep workflow configurable for future multi-step approvals.

──────────────────────────────────────────────────────────────────────────────
MODULE GROUP 4 — OFFICE OPS (Company Workspace + Admin Processing in HR/Admin Workspace)

A) Request Types (employee submits; admin processes)
1) Purchase Requests (PR)
- Employee submits item list (amazon links), justification, needed-by, attachments.
- Status: Draft -> Submitted -> Pending CEO -> Approved/Rejected -> Ordered -> Received -> Closed.
- Office Admin handles Ordered/Received + invoice attachments.

2) Travel Requests + Bookings
- Travel request: purpose, dates, from/to, constraints.
- Status: Draft -> Submitted -> Pending CEO -> Approved/Rejected -> Booked -> Completed -> Closed.
- Booking records: PNR/tickets, vendor, invoices, costs.

3) Admin/Office Tickets + IT Tickets (helpdesk)
- Tickets do NOT require CEO approval unless they create a PR/Travel/Payment entity.
- Status workflow + SLA + comments + attachments.
- Office Admin queue view.

B) Vendor Registry (general)
- vendors table: categories, contacts, GSTIN, payment terms, docs.
- Vendor bank details restricted to Office Admin + Finance.

C) Payment Tracker (finance comms layer, not Zoho replacement)
- payment items linked to PR/Travel/vendor invoice.
- Status: Requested -> Submitted -> Pending CEO -> Approved -> SentToFinance -> Processing -> Paid / Hold / Rejected.
- Finance updates processing/paid + reference; store invoice links.

D) Office Events & Facilities (add this — office OS gap)
- Company events calendar: townhall, offsite, trainings; RSVP; attendance list.
- Visitor management (light): visitor log, meeting host, check-in/out, NDA policy link.
- Facilities requests: repairs, housekeeping, access cards; track SLA.

E) Internal Requests (add this — high ROI)
- Letter requests (HR): experience letter, employment letter, visa letter, etc. (template-driven).
- Access requests: GitHub/Slack/email groups (ticketed; ties to onboarding/offboarding).
