# Components & UI Patterns — reference

The one place to look before building UI. Living doc — we grow it as we standardize more.

- `ui/` — shadcn/ui **primitives** (button, card, dialog, …). Library files; keep them flat & pristine (don't restructure or hand-edit — they're regenerated by the shadcn CLI).
- `shared/` — components used by **2+ features**. Everything else now lives with its
  feature under `features/<name>/components/`, and the app shell (sidebar, header)
  lives in `app/layout/`. See [../README.md](../README.md) for the screen map.

## Pattern: the "record card"

A horizontal, clickable summary card used for list rows across the app. Pioneered by the **reimbursement approval cards** (`features/requests/pages/service-catalog-page.tsx`) and reused by the **vehicle Travel-Timeline cards** and **rental-request cards** (`features/vehicles/`), and the booking **details rows**. Keep new record cards consistent with this anatomy so they don't drift.

**Anatomy (left → right):**
1. **Type icon** — filled rounded tint box (`h-10/11 w-10/11 rounded-xl`), colored by domain (brand blue / teal / coral).
2. **Identity** (`flex-1 min-w-0`) — bold title (`text-[15px] font-bold` / `text-sm font-bold`) + a muted subtitle line; small status/type badges may sit inline with the title.
3. **Primary divider** — thicker & darker than inner separators: `w-[1.4px] h-11 rounded-full bg-foreground/25 hidden md:block`.
4. **Labeled stat columns** — a `hidden md:flex items-stretch gap-5` group; each column is
   `icon (h-3.5 w-3.5 text-muted-foreground)` → `label` (`text-[10px] leading-none uppercase tracking-wide text-muted-foreground`) → `value` (`text-xs text-foreground`, only the primary datum bold). Columns are divided by thin vertical `<Separator orientation="vertical" className="h-11" />`. Give columns **fixed widths** so they line up across rows.
5. **Chevron** — `ChevronRight h-4 w-4 text-muted-foreground` on the far right when the card opens a detail popup.

**Container:** `card-surface card-hover rounded-2xl px-4 py-3.5 flex items-center gap-3/4`. On narrow widths, collapse the stat columns to a compact right-aligned summary (see `RentalRequestCard` / timeline `renderCard` in `features/vehicles/`).

**Priority accent:** for time-sensitive rows, add a coral ring (`ring-1 ring-[#FF6F62]/50`) + a "Due Soon" badge (see rental requests).

> When we next build a card that needs this, extract a small `StatColumn` (icon + label + value) building block into `components/` so record cards literally can't drift.

## Pattern: the "filter toolbar"

The search + filters + view-toggle + category-pills bar that sits under a page heading (`features/employees/components/employees-sections.tsx` is the fullest example; also `assets`, `holidays`, `my-requests`, `vehicles`, `attendance`, `company-workspace`).

None of these are components yet — every page hand-rolls the markup, so **copy from here, not from a neighbouring page**, several of which have drifted (see the table at the end).

### Assembly

Two rows, each a direct child of the page's `space-y-6` root (so 24px between them):

```tsx
{/* Row 1 — search · filters · view toggle */}
<div className="flex items-center gap-3 flex-wrap">
  {/* …search, selects, toggle… */}
</div>

{/* Row 2 — category pills (left, fills) · Select entry (right) */}
<div className="flex items-center gap-2 flex-wrap">
  <div className="flex gap-2 flex-wrap flex-1">{/* …pills… */}</div>
  {/* …Select button… */}
</div>
```

Row 1 uses `gap-3` (12px), row 2 `gap-2` (8px).

### 1. Search field

The search icon is **absolutely positioned inside** the input; the input gets left padding to clear it. There is no wrapper component — this exact block is repeated in ~8 pages.

```tsx
<div className="relative flex-1 min-w-48">
  <Search className="absolute left-3 top-1/2 -translate-y-1/2 h-4 w-4 text-muted-foreground" />
  <Input
    placeholder="Search by name, email, or code..."
    value={search}
    onChange={(e) => setSearch(e.target.value)}
    className="pl-9"
    data-testid="input-search-employees"
  />
</div>
```

- `flex-1 min-w-48` — the search is the only flexible item in row 1; everything else is fixed-width.
- `pl-9` (36px) clears the `left-3` + 16px icon. Don't change one without the other.
- Placeholder style: sentence case, lists the matched fields, trailing `...` — *"Search by name, email, or code..."*.
- Height/radius come from the `Input` base: **`h-10` (40px), `rounded-[16px]`, `opacity-80`, `border-input`**. Don't override.

### 2. Filter dropdowns

Plain shadcn `Select`. Leave the trigger height alone; set only a width.

```tsx
<Select value={locFilter} onValueChange={setLocFilter}>
  <SelectTrigger className="w-36" data-testid="select-loc-filter">
    <SelectValue placeholder="Location" />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="all">All Locations</SelectItem>
    {allLocations.map((l) => <SelectItem key={l} value={l}>{l}</SelectItem>)}
  </SelectContent>
</Select>
```

- **Widths:** `w-32` (128px) for short value sets, `w-36` (144px) for names/locations. Fixed, never `flex-1`.
- **The "all" option is a real `SelectItem`**, valued `"all"`, labelled `All <Plural>` — not a placeholder. State initialises to `"all"` so the trigger always shows a label. (`statusFilter` is the exception: it defaults to `"active"` and puts `All Status` last.)
- Trigger geometry comes from the `SelectTrigger` base: **`h-10`, `rounded-[16px]`, `opacity-80`**. Matches `Input` exactly, which is what makes the row align.

> **Height gotcha.** `SelectTrigger` and `Input` set `h-10`, so a `className="h-9"` *does* override them. `Button` sets **`min-h-10`** on every size (including `sm`), so `className="h-9"` on a Button is a **no-op**. Passing `h-9` to some controls in a row and not others therefore yields a 36px/40px mismatch rather than a uniformly shorter row — this is exactly what happened in `company-workspace.tsx`. Keep filter rows at the default 40px.

### 3. View toggle (segmented)

Container carries `.segmented-toggle` (1px white stroke, 12px radius); children are plain buttons. **Use the `.btn-primary-gradient` class for the active state — never inline a gradient.**

```tsx
<div className="segmented-toggle inline-flex p-0.5 h-9 flex-shrink-0">
  {viewButtons.map((b) => (
    <button
      key={b.v}
      onClick={() => setViewMode(b.v)}
      aria-label={`${b.label} view`}
      data-testid={`view-mode-${b.v}`}
      className={`px-3 h-full rounded-[10px] text-xs font-medium inline-flex items-center justify-center gap-1.5 ${
        viewMode === b.v ? "btn-primary-gradient text-white" : "text-muted-foreground"
      }`}
    >
      <b.icon className="h-4 w-4" />
    </button>
  ))}
</div>
```

- **Geometry:** `p-0.5` + `h-9` on the container, `rounded-[10px]` on the children. The 2px padding against a 12px outer radius makes 10px the concentric inner radius — the two values move together.
- Use `h-10` instead when the toggle sits in a row of default-height controls (`my-requests.tsx`), `h-8` only inside a card header (`vehicles.tsx:1828`).
- Icon-only: `h-4 w-4` glyph, always with an `aria-label` or `title`. Icon + text: add `gap-1.5` and a `h-3.5 w-3.5` glyph.
- Inactive ink is `text-muted-foreground` (or `text-foreground/70` over a tinted card).

### 4. Filter pills (categories / departments)

Full-round pills, active = the primary gradient. Counts go in the label.

```tsx
<button
  onClick={() => setDeptFilter("all")}
  data-testid="filter-dept-all"
  className={`px-3 py-1.5 rounded-full text-xs font-medium transition-colors ${
    deptFilter === "all"
      ? "btn-primary-gradient text-white"
      : "bg-muted text-muted-foreground border border-border hover-elevate"
  }`}
>
  All Departments ({employees.length})
</button>
```

- Always lead with an **`All <Things> (n)`** pill, then the individual pills, each `Name (n)`.
- **Filter out empty buckets** — `deptCounts.filter((d) => d.count > 0)` — so a pill never reads `(0)`.
- `py-1.5` (not `py-1`), and inactive pills carry `border border-border` + `hover-elevate`.

### 5. `Select` (selection mode) + the selection bar

Entering selection mode is an explicit button on the right of the pill row; it swaps itself for a bar of bulk actions.

```tsx
{!selectionMode && (
  <Button variant="secondary" size="sm" className="flex-shrink-0"
    onClick={() => setSelectionMode(true)} data-testid="button-select">
    <MousePointerClick className="h-4 w-4 mr-1" /> Select
  </Button>
)}
```

```tsx
{selectionMode && (
  <Card className="border-0"><CardContent className="p-3 flex items-center justify-between gap-3 flex-wrap">
    <div className="flex items-center gap-3">
      <Button variant="outline" size="sm" onClick={toggleAll} data-testid="button-select-all">
        <CheckSquare className="h-4 w-4 mr-1" /> Select All
      </Button>
      <span className="text-sm font-medium">{selected.size} selected</span>
    </div>
    <div className="flex items-center gap-2">
      <Button variant="secondary" size="sm" disabled={selected.size === 0} onClick={/* export */}>
        <Download className="h-4 w-4 mr-1" /> Bulk Export
      </Button>
      {canManage && <Button variant="secondary" size="sm" disabled={selected.size === 0} onClick={/* bulk edit */}>
        <Pencil className="h-4 w-4 mr-1" /> Bulk Update
      </Button>}
      <Button variant="outline" size="icon" className="h-9 w-9 flex-shrink-0" onClick={exitSelection}
        aria-label="Exit selection" data-testid="button-exit-selection"><X className="h-4 w-4" /></Button>
    </div>
  </CardContent></Card>
)}
```

Rules: selection state is a `Set<string>`; `Select All` acts on the **filtered** list, not the full one; exiting always clears the set (`exitSelection = () => { setSelectionMode(false); clearSel(); }`); bulk actions stay rendered but `disabled` at zero selection rather than hidden. Same pattern in `company-workspace.tsx` (`ReimbApprovals`).

### Known drift — do not copy these

| Where | What's wrong |
|---|---|
| `features/employees/lib/employee-constants.ts` (`ACTIVE_TAB_STYLE`) | Local `ACTIVE_TAB_STYLE` inline gradient on the view toggle — a *different* gradient from `.btn-primary-gradient` (reversed direction, no `#4BDCD9` stop, black border instead of white). Use the class. |
| `features/employees/components/employees-sections.tsx`, `features/holidays/components/holidays-sections.tsx` | Toggle uses `p-1` + `rounded-[8px]` + `h-8`; the other 8 usages use `p-0.5` + `rounded-[10px]` + `h-9`. |
| `features/requests/pages/service-catalog-page.tsx` | Filter selects forced to `h-9 ... text-xs` while sibling Buttons stay 40px (`min-h-10` ignores `h-9`) — a 36/40 mismatch. |
| `features/announcements/components/announcements-sections.tsx`, `features/shifts/pages/shifts-page.tsx` | Pills use flat `bg-primary text-primary-foreground` for active instead of `btn-primary-gradient text-white`. `shifts` also uses `py-1` instead of `py-1.5`. |
| `features/assets/components/assets-sections.tsx` (`CategoryChips`) | Pills tint by a per-category colour map rather than showing an active/inactive state at all — check whether that's intentional before copying it as a filter. |

> Per the extraction rule above, all five blocks are past the 2-page threshold and want extracting into `SearchInput` / `FilterSelect` / `SegmentedToggle` / `FilterPills` / `SelectionBar` in `shared/`.
> Each feature currently has its own copy in `features/<name>/components/<name>-sections.tsx`; those are the places to reconcile. Until that happens this section is the source of truth.
